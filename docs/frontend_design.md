# arch_then_mcts_then_u2e_ppw 前端设计规范

## 一、设计语言

### 1.1 定位

科研驾驶舱（Research Cockpit）。用户是算法研究员，长时间盯着屏幕等待优化结果，需要：
- **信息密度高**，不浪费空间
- **暗色调**，护眼，突出数据
- **关键决策点醒目**，Gate 操作绝不能误触
- **进度始终可感知**，消除焦虑

### 1.2 色彩系统

```
背景层次（深色体系）
  --bg-base:       #0d0f14   全局背景
  --bg-surface:    #151820   卡片/面板
  --bg-elevated:   #1e2230   悬浮/选中
  --bg-overlay:    #252a3a   模态/tooltip

边框
  --border-subtle: #2a2f42   默认分隔线
  --border-strong: #3d4560   强调分隔线

文字
  --text-primary:  #e8eaf2   正文
  --text-secondary:#8a90a8   次要信息
  --text-muted:    #545975   占位/禁用

功能色
  --accent-blue:   #4f8ef7   主操作、链接、当前步骤
  --accent-teal:   #34c8a0   成功、提升、正向指标
  --accent-amber:  #f5a623   警告、Gate 等待、次要操作
  --accent-red:    #e05c5c   失败、错误、危险操作
  --accent-purple: #9b7ef8   MCTS 节点、搜索路径

数据可视化序列（搜索树、进化曲线）
  --data-1: #4f8ef7   frontier 节点
  --data-2: #34c8a0   最优节点
  --data-3: #9b7ef8   历史节点
  --data-4: #f5a623   人工选中节点
  --data-5: #e05c5c   失败节点（score=-999）
```

### 1.3 字体

```
代码/数据:    JetBrains Mono, monospace   — 分数、代码 diff、日志
标题:         Inter 600                   — 卡片标题、阶段名
正文:         Inter 400                   — 说明文字
数字大展示:   Inter 700 tabular-nums      — 大分数、计数器
```

### 1.4 间距与圆角

```
基础单位: 4px
卡片圆角: 10px（内嵌子卡片: 6px）
按钮圆角: 6px（危险操作: 8px，更大点击区）
阴影:     0 2px 12px rgba(0,0,0,0.4)
```

**动效细节**：
- 当前步骤的图标是旋转的 spinner（CSS `animation: spin 1s linear infinite`）

- `loop_to` 重试时，对应步骤短暂 shake 动画后图标变为 `↺`，并在旁边显示 "重试第 N 次"
- 右侧树节点逐步出现（fade-in），代码函数名在叶子定义阶段才填充进来

## 四、实时通信架构

### 4.1 后端接口设计

```
WebSocket: ws://host/ws/runs/{run_id}/events
  → 事件类型:
    { type: "step_start",   step_id, phase }
    { type: "step_done",    step_id, outputs }
    { type: "step_error",   step_id, error }
    { type: "gate_waiting", gate_id, payload }
    { type: "log_line",     step_id, text }
    { type: "run_done",     outputs }
    { type: "run_error",    error }

REST POST: /api/runs/{run_id}/gate/{gate_id}
  Body:
    arch_gate:  { feedback?: string }           // 空=批准
    mcts_gate:  { action, next_mode, selected_ids? }
```

### 4.2 前端状态机

```
RunState:
  phase: 0~7
  stepStates: Map<step_id, "pending"|"running"|"done"|"error">
  stepOutputs: Map<step_id, any>
  gateState: null | { gate_id, payload, waiting: true }
  metrics: { baseline, currentBest, improvement }
  logs: Map<step_id, string[]>

事件处理:
  step_start  → stepStates[id] = "running"
  step_done   → stepStates[id] = "done"; stepOutputs[id] = outputs; 推进 phase
  gate_waiting → gateState = { ... }  // 触发 Gate UI 接管
  log_line    → logs[id].push(text)   // 仅在面板展开时渲染（虚拟滚动）
```

## 六、关键 UX 原则

1. **Gate 防误触**：批准/停止类按钮统一使用 800ms 长按或倒计时确认，避免意外终止长时任务
2. **进度始终可感**：任何超过 5 秒的步骤必须有动态进度指示（spinner / 进度条 / 计时器）
3. **错误可诊断**：step_error 时，卡片变红并展示完整错误信息 + "查看完整日志" 链接，而不是仅显示"失败"
4. **断线续连**：页面刷新后通过 run_id 重连 WebSocket，从 stepOutputs 快照恢复 UI 状态
5. **移动端降级**：Gate 决策面板在移动端全屏展示，保证审核操作可用（其余面板折叠）
